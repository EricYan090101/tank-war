# 坦克大战：随机地图版

使用 Go 和 Ebitengine。项目根目录执行 `go run .` 启动，`go test ./...` 执行测试。

## 当前玩法

每次开始新游戏生成新的随机种子，每关生成新地图。保留 26×26 地块、32 像素坦克、砖墙破坏、基地防守和现有敌人配置。旧地图文件保留，但默认战斗不再加载它们。

WASD 移动，空格射击，P 暂停。战斗中 ESC 后按 Y 结束本局并结算；关卡开始页按 Enter 开始，过关后 Enter 进入下一关，ESC 结束本局。基地被毁或所有玩家生命耗尽也会结算。最终成绩停留到按 Enter 返回标题；最高分只在本次程序运行中保留。

## 地图生成与评估

生成器按 32×32 区块随机放置地形，再从三个敌方出生点挖出曲折通路，并保留底部防守横通道、玩家出生区和基地砖墙。通路判定使用完整 32×32 坦克碰撞框，BFS 搜索步长为 16 像素。

地图难度在开局时冻结为 0–100 分，避免战斗中拆墙改变奖励。当前为规则估计，不是实测胜率，也没有自动调整敌人或筛选目标难度：

- 45%：三个敌方出生点到基地前沿的最短路径压力。路径越短，压力越高。
- 25%：可达位置中有至少三个相邻方向的位置比例，作为多方向进攻的近似指标。
- 20%：可达位置的草丛比例。
- 10%：可达位置的冰面比例。

上述都是启发式指标，尤其岔路和开阔地对难度的影响仍需试玩校准；当前敌人并不使用该 BFS 作为 AI 寻路。结算页显示最后一张地图的种子，调用 `Map.GenerateRandom(seed)` 可复现相同地图。

## 计分

每关基础分 = 原有敌人击杀分 + 通关奖励 1000 分（未通关不奖励）。

每关地图加分 = 向下取整（本关基础分 × 地图难度 / 200）。例如本关基础分 3000、地图难度 60，地图加分为 900。

本局最终分为各关基础分和地图加分之和，包括最后未完成关卡已获得的分数。每关只结算一次，之前关卡的加分不会再参与乘算。炸弹击杀沿用原有击杀分。结算页显示基础分、地图加分、总分、累计击杀、通关数和结束原因。

## 验证范围

自动测试覆盖 500 个种子的出生点/防守区可达性、基地和砖块完整性、地图多样性、同种子复现，以及跨关和最终结算的防重复加分。仍需实际试玩检查手感、画面和难度权重。

随机地图难度加分和累计成绩属于街机模式。竞技模式现已单独实现房主权威联机、等待大厅和回合赛制，详见下面的竞技房间说明；合作模式已实现 1–4 人大厅及房主权威战斗同步，详见文末说明。

## 出兵与操作更新

过场、菜单和最终结算统一用 Enter 确认，空格只用于玩家一射击。开始关卡前等待 Enter，不再倒计时自动进入。

按本项目的自定义要求，取消四辆敌人同屏上限；每关总数仍为 20。敌人从左、中、右三个顶部出生点循环出现，第一关间隔 180 帧（60 TPS 下为 3 秒），后续每关减少 6 帧，最低 90 帧。出生点被玩家或其他敌人占用时等待，空出来立即恢复，不叠放坦克。这个无同屏上限的规则是本项目的改动，不代表原版规则。出生星光持续 45 帧，期间不移动、不开火且不受子弹或炸弹伤害。

修正敌方贴图的原始朝向：图片炮管朝上，出生时旋转朝下，显示方向与移动和射击一致。敌人之间阻挡，每辆敌人最多保留一发在场子弹，不再共用四发子弹上限。

玩家移动速度固定为每帧 2 像素，普通敌人 1 像素、快速敌人 2 像素。转向优先响应最新按下的方向键，并对齐 16 像素通道；对齐过程逐步检测障碍，不能穿墙或穿过坦克。普通地面松键即停，冰面松键后最多滑行 24 帧，离开冰面或撞墙即停。射击冷却缩短为 8 帧，升级子弹速度为每帧 6 像素；玩家子弹额度按玩家分别计算。这些参数是本项目的手感调校，尚未做原版逐帧对照。

## 清场后的自由活动

击毁本关最后一辆敌人后，进入 180 帧（3 秒）自由活动时间。此时清除残留子弹、停止射击和出兵，玩家仍能移动和拾取道具，结束后显示关卡结算。Enter 可提前进入结算；P 暂停会同时暂停倒计时。通关奖励只计入一次，地图加分在进入结算时确定；主动结束本局也不会漏算或重复计算。

## 火炮的原版升级顺序

| 已收集星星 | 内部 Power | 子弹速度 | 在场子弹上限 | 钢墙 |
| --- | --- | --- | --- | --- |
| 0 | 1 | 普通 | 1 | 不可破坏 |
| 1 | 2 | 高速 | 1 | 不可破坏 |
| 2 | 3 | 高速 | 2 | 不可破坏 |
| 3 | 4 | 高速 | 2 | 可破坏 |

三颗星封顶，满级炮弹有更大的砖墙破坏范围。火炮升级不增加对装甲敌人的单发伤害：装甲敌人仍需四次有效命中。死亡后回到初始火炮，跨关保留升级；两名玩家各自计算子弹上限。顺序参考 [Battle City 攻略](https://gamefaqs.gamespot.com/nes/562966-battle-city/faqs/29287) 和 [Gameplay 说明](https://strategywiki.org/wiki/Battle_City/Gameplay)。当前弹速仍采用本项目已有像素尺度与调校值，没有声称逐帧复现原机。

## 界面与预览

标题、模式选择、创建/查找房间、房间名输入、关卡说明、战斗侧栏、暂停/退出弹窗、清场提示、关卡结算和最终成绩已统一为深色像素风。自带位图字体，不需额外下载。默认窗口按 2 倍整数比例显示，避免拉伸。

`go run ./cmd/uipreview` 使用真实游戏渲染器导出 29 个界面到 `previews/`，用于检查布局。预览使用固定示例数据，不代表玩家的真实成绩。功能测试覆盖清场计时、暂停/跳过、最后道具拾取、三星升级、钢墙破坏条件、装甲命中次数，以及之前的随机地图和计分规则。

## 半透明提示与计分动画

战斗中的道具提示、冻结倒计时、清场提示及暂停/结束弹窗使用半透明底板，文字保持不透明；菜单和成绩卡片保持实色。提示底板约 61% 不透明度，可以看到后面的战场。

每关结算先依次统计四类敌人的击杀数量和分值，再统计通关奖励、地图加分，累计总分随之上涨，当前计分项会高亮。没有击杀的类别自动跳过。动画约 1–4.3 秒，取决于本关计分项目；动画中 Enter 立即显示最终数值，再按一次 Enter 进入下一关。ESC 仍可结束本局。

计分动画仅改变显示，实际成绩在结算时已经记入，不会因跳过或退出而少算、重复加分。`go run ./cmd/uipreview` 还会导出计分中间画面和 `previews/16-count-animation.gif` 动画预览。

## 调整窗口大小

支持拖动窗口边缘或角落调整大小，也可以使用标题栏的最大化按钮。初始窗口为 1152×832，最小内容尺寸为 576×416。游戏保持固定的逻辑画面比例并自动缩放；窗口比例不同时留边，不拉伸地图或改变移动、碰撞规则。

## 竞技房间：1v1 / 2v2

进入 VERSUS MATCH，再选择 CREATE ROOM、填写房间名。模式页上方为 1v1，下方为 2v2，支持鼠标点击或上下键加 Enter。选择 2v2 后先选择 GREEN TEAM（绿队）或 YELLOW TEAM（黄队），然后选择 BEST OF 3/5/7（分别为三局两胜、五局三胜、七局四胜）创建等待大厅；1v1 直接进入赛制选择。其他电脑进入 VERSUS MATCH → FIND ROOM 加入同一局域网房间。大厅显示每个玩家的编号、队伍和连接状态；1v1 要求 2 人，2v2 要求 4 人，2v2 加入者也需选择队伍，每队最多两人，大厅按 T 可重新选队。满员且双方人数齐备后，只有房主能按 Enter 开始，开局后锁定队伍。

- 1v1 房主在下方、对手在上方；2v2 根据玩家实际选队决定出生位置、坦克颜色、友伤判定和比分归属。每台电脑都用 WASD 移动、空格射击。
- 每回合地图上下镜像，双方出生区和通路对等，无基地、电脑敌人和升级道具，所有玩家使用初始单发火炮。
- 每辆坦克承受 3 次有效命中后淘汰，不在本回合复活。队友子弹不造成伤害。下一回合双方一起复活、清零受击次数，保留队伍比分。
- 2v2 必须淘汰对方两人才能得一分；同时全灭算平局，不加分，再进行一回合。先得到 2/3/4 分的队伍赢得整场。平局可能使实际回合数超过赛制标称局数。
- 战斗侧栏只显示双方回合胜场及每个玩家的受击次数。开局有 2 秒倒计时，回合结束展示 3 秒结果后进入下一回合。比赛结束由房主按 Enter 返回大厅，可再次开始。
- ESC 可离开等待房间；战斗中 ESC 后 Y 确认离开，N 取消。联机比赛不暂停，退出确认期间只停止本机输入。比赛中有人断开会返回大厅并重置本场比分，待满员后房主重新开始；房主退出会关闭房间。

房主统一计算碰撞、命中、回合和比分，客户端发送操作并接收完整地图、坦克、子弹和爆炸状态。房间发现使用 UDP 9988，战斗连接使用 TCP 9989；当前支持局域网，不包含互联网中继或断线续赛。游戏失去焦点时仍运行，避免切换窗口导致房间断开。

验证包含 100 个竞技地图种子的镜像和出生点连通性、3 次命中/友伤/团队淘汰/各赛制，以及实际本机 TCP 的 2 人和 4 人房间、满员开局、额外玩家拒绝、输入与战场同步、掉线和补位。尚需使用不同电脑进行局域网实机联调。


## 联机昵称、队伍颜色与本地视角

选择 VERSUS MATCH 后先输入昵称（1–12 位英文字母、数字、短横线或下划线；当前像素字体不支持中文昵称），再创建或查找房间。昵称通过房主同步，在大厅、坦克上方、受击信息板和最终成绩页显示。

选队改为 GREEN TEAM（绿队）和 YELLOW TEAM（黄队），卡片使用对应颜色并显示当前人数 / 2，已满队伍标记 FULL。创建前显示 0 / 2 和 NEW ROOM；加入房间后实时显示房主同步的人数。开局前仍可按 T 换队。

每位玩家都看到己方从底部出发：绿队客户端将战场旋转 180 度，并转换 WASD 的输入方向；黄队保持原视角。名字、信息板和弹窗保持正向显示。服务器统一使用原始地图坐标，不改变碰撞和命中规则。队伍名称不再依赖屏幕上下位置。


房间搜索列表每页显示三个房间，每项包含房间名、当前人数 / 人数上限、1v1 或 2v2、BEST OF 3/5/7 与 FIRST TO 2/3/4 WINS（先赢几局获胜）、房主 IP，以及 OPEN / FULL / PLAYING 状态。上下键翻页选择，Enter 加入。


## 可点击按钮与四人合作大厅

退出确认使用“继续”和“结束 / 离开”两个独立按钮。主要菜单卡片、房间列表、开始、返回、暂停/继续、过场与结算操作支持鼠标点击，同时保留按钮标示的键盘快捷键。

合作模式创建房间后进入等待大厅，显示四个席位及实时连接状态。人数上限包含房主，共 4 人；房主可在 1–4 人时点击 START GAME 或按 Enter 开始，不需要满员。开始操作与加入检查在服务器同一锁下完成，开局后拒绝所有新连接，即使中途有人退出也不开放补位。

合作战斗由房主统一模拟，客户端使用 WASD 和空格控制各自坦克；地图、敌人、子弹、道具、生命与成绩同步。房主控制暂停、跨关和结束整局。客户端离开只移除该玩家，房主关闭房间会断开所有客户端。已验证本机 TCP 的 1–4 人开局、拒绝第五人、拒绝中途加入、等待大厅掉线补位及状态同步；不同电脑的局域网实机体验仍需验证。


## 简洁界面更新

统一删除装饰标语、重复操作说明和技术性小字。模式选择使用同色坦克加盾牌表示合作防守，黄绿坦克对阵表示玩家对战；1v1 / 2v2 用对应数量的坦克图标展示。按钮简化为 START / BACK / JOIN 等短标签，鼠标与原有快捷键仍可使用。房间人数、胜局要求、昵称、比分与必要错误提示保留，结算数字加大。


## 六种新素材

已将批准的像素风概念整理成六张独立 PNG：Source/Pictures 下的 water.png、brick.png、stone.png、bush.png（现为灰紫烟雾）、player_yellow.png 和 player_green.png。地形覆盖旧同名图片；玩家坦克接入图片渲染，替代旧矩形绘制，菜单中的坦克图标也使用新素材。背景改为黑色。烟雾保留透明通道，叠加透明度系数 0.88，覆盖在坦克上方；砖墙仍按四块破坏。

素材通过内置 imagegen 生成，完整提示词与参考图片记录在 assets/generated-art-prompts.json。使用时按游戏尺寸缩放，原始高清文件保留在上述 PNG 中。


## 连片河水规则

合作与竞技地图中的每片河水至少包含 3 个按上下左右相连的 32×32 生成区块（共至少 12 个 16×16 地块；斜角接触不算连接）。规则在通路开凿后应用：不足三块的水域优先向相邻砖墙或石墙扩展，不侵占已留出的空地、烟雾、冰面及出生通路；没有足够空间的零散水域改为空地。竞技模式先处理上半场再镜像，保持双方地形一致。相同种子在当前版本仍可复现。

Smoke regions contain at least four orthogonally connected 32px generation blocks (16 small cells), with unrestricted shapes. Growth preserves water, ice, carved routes and spawn strips; versus terrain stays mirrored. Smoke uses overlapping soft transparent clouds and ice uses the approved pale-blue snow texture.

Iron shield: pickups refill three hits of persistent protection; each bullet consumes one hit regardless of power, and the third breaks the shield without damaging the hull. Spawned enemies have a 25% chance of carrying the same shield. Players start the first stage/round with three-hit iron armor. Timed respawn invulnerability and the heavy enemy type have been removed. Shield durability is synchronized by the host.

On final player death or base destruction, the battlefield remains visible beneath a red GAME OVER fade for 2.5 seconds, followed by animated score settlement. Base destruction leaves a complete ruined headquarters sprite. This transition is synchronized in cooperative play.
